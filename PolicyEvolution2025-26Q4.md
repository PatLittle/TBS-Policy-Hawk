## 2026-01-15 — Guide on the Exceptional Contracting Limit for Sustained Emergencies of National Importance

**Issue:** [#274](https://github.com/PatLittle/TBS-Policy-Hawk/issues/274)  
**Document ID:** 32825  
**Category:** Guide  
**GUID:** `32825_2026-01-15`  
**Change type:** policy_update

### Policy change analysis

The raw XML stored for `32825_2026-01-15` is a **Request Rejected** gateway page and was not used as evidence. No earlier repository copy of this Guide was found. The readable current Markdown posted on issue #274 was assessed alongside the related prior notice:

- New/current readable evidence: issue #274’s `Current Version (Markdown)` comment (captured 2026-09-17)
- Closest related prior repository evidence: `data/PINs/CPN/Exceptional_Contracting_Limit_for_Sustained_Emergencies_of_National_Importance_for_Public_Services_and_Procurement_Canada_and_Shared_Services_Canada.md` (Contracting Policy Notice 2023-4)

### Summary

This is a new, detailed operational Guide for the existing SENI exceptional contracting-limit framework described in Contracting Policy Notice 2023-4. It does not, on the available evidence, create a new procurement authority; it explains the approval, conditions, reporting, funding, extension, and lessons-learned processes for use of the authority.

### Substantive changes identified

| Area | Evidence before / previous state | Evidence now | Interpretation |
|---|---|---|---|
| **Operational guidance** | The 2023 notice announced the framework and said that further guidance would be developed and distributed. | The Guide sets out eligibility, written-request content, approval communications, ongoing legal/policy duties, extensions, liability, Vote 5 funding, and appendices. | Converts a high-level notice into a usable end-to-end operating process. |
| **Reporting and lessons learned** | Approval would set reporting; PSPC or SSC would provide a lessons-learned report at least after final expiry. | Approval conditions specify reporting to the Assistant Secretary, Government Operations, with Appendix C data elements; a lessons-learned report is due within three months after expiry (including extensions) and Appendix D defines its contents. | Makes oversight expectations more concrete and time-bound. |
| **Authority scope** | On approval, PSPC or SSC could contract without value limit, limit/indemnify liability, and make cross-fiscal-year advance payments. | The Guide describes the same exceptional tools while making clear that the President’s approval may impose an effective period, reporting, and other conditions. | Confirms the existing authority while emphasizing conditional, time-limited use rather than unrestricted emergency discretion. |

### Practical effect

1. **Prepared request packages:** PSPC/SSC and supporting departments can use the Guide’s requested evidence and Appendix B steps to prepare a SENI request.
2. **Governance controls:** Approved use should be managed against the President’s conditions, Appendix C data reporting, and the three-month lessons-learned deadline.
3. **Funding coordination:** Potential Treasury Board Vote 5 access and its CFO-supported request are now explicitly integrated with the contracting process.

### Watch item

The Guide itself lacks a valid raw repository capture and has no earlier same-document copy, so this is a new-guidance analysis, not a line-by-line amendment diff. Replace the rejected XML with a successful source capture before relying on it as the authoritative archived text.

### Summary

The Standard’s note to reader says it was amended to align with the December 17, 2025 amendments to the *Accessible Canada Regulations* concerning digital technologies. The comparison shows a revised policy-framework reference and a restructuring of the mobile-application requirement appendices, including removal of the separately named accessibility requirement. Because the current raw XML is invalid, these findings are limited to the readable Markdown evidence.

### Substantive changes identified

| Section | Prior version | New/current version | Interpretation |
|---|---|---|---|
| **Note to reader / accessibility framework** | Stated that the Standard was under review to realign dates for the Web Renewal Initiative. | States that it was amended for recent *Accessible Canada Regulations* changes and points to CIO direction on accessible digital technologies. | Reframes the instrument around the current accessibility regulatory context. |
| **3.6–3.8 — policy references and authority** | Supported the *Policy on Management of Information Technology*; cited its section 3.5 as part of the issuance authority; required reading included the *Standard on Web Accessibility*. | Supports the *Policy on Service and Digital*; issuance authority cites the *Financial Administration Act* only; required reading lists Web Usability and Web Interoperability, not the Web Accessibility Standard. | Updates the governing policy framework and removes the retired/older accessibility-standard cross-reference. |
| **6.1.1.2.3–6.1.1.2.6 and Appendices C–F** | Separate requirements covered accessibility (Appendix C), usability (D), interoperability (E), and publishing (F). | Requirements cover usability (C), interoperability (D), publishing (E), and the Technical Specifications for the Web and Mobile Presence; the roll-out schedule is Appendix F. | The standalone accessibility appendix/requirement appears removed and the remaining operational requirements are renumbered and consolidated. Accessibility remains an expressed objective, but implementers should confirm how the Regulation/CIO direction now supplies the detailed accessibility standard. |

### Practical effect

1. **Reference maintenance:** Departments should update implementation material that still relies on the former *Policy on Management of Information Technology* or *Standard on Web Accessibility* references.
2. **Requirement mapping:** Mobile-app checklists should be remapped to the current Appendix C–E structure and the Technical Specifications reference.
3. **Accessibility assurance:** The amended note points to the *Accessible Canada Regulations* and CIO direction; confirm compliance controls against those sources rather than assuming the former Appendix C remains in force.

### Non-substantive changes

The older XML contains encoding artifacts and an obsolete Appendix-G anchor. Those presentation differences were not treated as substantive except where the corresponding current Markdown shows a changed requirement or reference.
